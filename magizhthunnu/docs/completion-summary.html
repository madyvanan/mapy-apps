Frontend — Key Modules

Critical files with their purpose and notable implementation details

frontend/src/main.tsx

Application Entry Point

Imports ./i18n as the very first statement — required so i18next initialises synchronously before any React component renders. Wraps app in StrictMode.

frontend/src/App.tsx

Root Component & Router

Provider chain: AuthProvider → CartProvider → BrowserRouter. All 15 routes with React.lazy. PrivateRoute redirects unauthenticated users to /auth/login with state.from for post-login return.

frontend/src/context/AuthContext.tsx

Auth State

useReducer with LOGIN | LOGOUT | SET_LOADING | UPDATE_PROFILE. Calls getMe() on mount. Exposes login, register, logout actions.

frontend/src/context/CartContext.tsx

Cart State

useReducer with ADD | REMOVE | UPDATE_QTY | CLEAR. ADD action silently blocks cross-restaurant items. Recalculates totalAmount + itemCount on every action.

frontend/src/services/api.ts

Axios Instance

withCredentials: true on all requests. 401 response interceptor attempts /api/auth/refresh once then redirects to login on second failure.

frontend/src/hooks/useSocket.ts

Socket.IO Hooks

useOrderSocket(orderId, onUpdate) — joins order:{id} room, listens to all order events. useRestaurantSocket(restaurantId, onNewOrder) — joins restaurant room.

frontend/src/i18n/

Internationalisation

react-i18next + LanguageDetector. Detection order: ['localStorage', 'navigator']. localStorage key magizhthunnu-lang. Fallback en. Two locale files mirror all keys.

frontend/src/components/ui/LanguageSwitcher.tsx

Language Toggle

Single button in Navbar. Displays 🇮🇳 தமிழ் when in English (invites switch to Tamil) and 🌐 English when in Tamil. Preference persists across reloads.

frontend/vite.config.ts

Vitest + Dev Proxy

Dev proxy: /api → localhost:5000, /socket.io → localhost:5000 (ws:true). Vitest: globals:true, environment:jsdom, setupFiles: setup.ts, v8 coverage.

Backend — Key Modules

Express server, 8 route modules, 7 MongoDB models, real-time infrastructure

server.ts — Middleware Registration Order (critical)

cors → helmet (CSP) → generalLimiter → morgan→winston → json({10mb}) → cookieParser → compression → routes

Auto-start guarded: if (process.env.NODE_ENV !== 'test') { start(); } — enables integration tests to import app without triggering DB connection.

routes/ — 8 modules

Route Modules

/api/auth (authLimiter)
/api/restaurants (public)
/api/cart (authenticate)
/api/orders (authenticate + orderLimiter)
/api/payments (webhook public!)
/api/reviews (create: auth)
/api/users (authenticate)
/api/admin (authenticate + admin role)

models/ — 7 collections

MongoDB Models & Indexes

users: email unique, role
restaurants: 2dsphere, cuisineTypes+isOpen compound, name text
menuItems: {restaurantId,category} compound
carts: userId unique, updatedAt TTL 24h
orders: idempotencyKey unique
payments: orderId unique
reviews: orderId unique (one per order)

services/auth.service.ts

Authentication

Access token: 900s (15min) — hardcoded as seconds for @types/jsonwebtoken compatibility. Refresh token: 604800s (7d). Refresh token stored in Redis key refresh:{userId}. bcrypt rounds: 12.

services/socket.service.ts

Socket.IO + Redis Pub/Sub

Channel order-events published via redisClient.publish. All Express instances subscribe via redisSub and relay to connected clients. Rooms: order:{id} + restaurant:{id}.

utils/asyncHandler.ts

Generic asyncHandler

Made generic: asyncHandler<TReq extends Request> with fn(req as TReq, res, next). Allows controllers that use AuthenticatedRequest to type-check correctly without unsafe casts.

queues/email.queue.ts

BullMQ Email Queue

Queue + Worker on the email queue. 5 retries with exponential backoff (1hr delay). Connection parsed from REDIS_URL env var. SMTP processor is a TODO — currently logs the job.

Security Architecture

Defence-in-depth: 8 security layers implemented

🪖

Helmet CSP

scriptSrc allows securegw.paytm.in; imgSrc allows Cloudinary; HSTS maxAge 31536000 with includeSubDomains

🍪

httpOnly Cookies

Access + refresh tokens in httpOnly + Secure + SameSite=Strict cookies — immune to XSS token theft

🔒

Zod Validation

All request bodies validated at route level via validate(schema) middleware before controllers. Returns 400 VALIDATION_ERROR on failure.

⏱️

Rate Limiting

General: 100/15min · Auth: 5/15min · Orders: 10/min. Redis-backed; skipped in test env.

✅

Paytm Checksum

Webhook rejects requests with invalid checksum. Production note: placeholder must be replaced with PaytmChecksum.verifySignature before go-live.

🔐

bcrypt ×12

Passwords hashed with 12 rounds on pre-save hook in User model. comparePassword instance method for login.

🛡️

RBAC Middleware

authenticate (verifies JWT cookie) + authorize(...roles) (checks role). Attach as asHandler(authorize('admin')) on routes.

🌍

.env Protection

.gitignore covers all .env files. .env.example files committed instead. MongoDB Atlas IP whitelist recommended for production.

Production TODO & Known Issues

Items that must be addressed before going live

⚠️ Paytm Checksum — CRITICAL before production

File: backend/src/services/payment.service.ts — verifyPaytmChecksum function is a placeholder that logs a warning and returns true. Replace with PaytmChecksum.verifySignature(body, PAYTM_MERCHANT_KEY, checksum) from the official Paytm Node SDK before deploying. Failure to do this allows unauthenticated webhook calls to confirm orders.

⚠️ JWT Token Expiry — Hardcoded Seconds

Access token TTL is hardcoded as 900 (15 min) and refresh token as 604800 (7 days) in auth.service.ts. Newer @types/jsonwebtoken rejects string format ('15m'). If ops needs configurable TTL, update to parse the env var to a number: parseInt(process.env.JWT_EXPIRES_IN) or import ms from the ms package.

⚠️ Frontend Test Coverage — Needs Expansion

Currently 1 smoke test (LanguageSwitcher.test.tsx) plus MSW handler infrastructure. The 80% coverage threshold is configured in vite.config.ts but will fail until more tests are written. Priority tests: AuthContext login/logout flow, CartContext cross-restaurant guard, CheckoutPage Paytm initiation.

ℹ️ BullMQ Email Worker — SMTP Not Integrated

File: backend/src/queues/email.queue.ts — Worker processor currently only logs the job. Integrate SendGrid or SMTP via nodemailer before order confirmation emails go live. Queue and retry logic (5 attempts, exponential backoff) are fully configured.
