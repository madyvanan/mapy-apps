Section 01
Executive Summary
Business context, goals, and stakeholders

Magizhthunnu (meaning "delightful" in Tamil) is a full-stack online food delivery platform connecting customers with local restaurants. Built on the MERN stack with TypeScript, it enables customers to browse restaurants, place orders, and pay digitally — while giving restaurants a management dashboard and admins a control plane.

🎯
Business Goals
  • Connect customers & local restaurants
  • Frictionless digital ordering experience
  • Integrated Paytm payment processing
  • Real-time order tracking
  • Admin & restaurant management dashboards
👥
User Roles
  • Customer — Browse, order, track, review
  • Restaurant Owner — Manage menu, orders, hours
  • Admin — Platform oversight, analytics
📦
Core Features
  • Restaurant discovery (geolocation)
  • Dynamic menu with customizations
  • Shopping cart with TTL auto-clear
  • Multi-step checkout & Paytm payments
  • Live order status (Socket.IO)
  • Ratings & reviews system
⚡
Non-Functional Requirements
  • Response time < 200ms (cached)
  • 99.9% uptime SLA
  • HTTPS + JWT security
  • Horizontal scalability
  • 80%+ test coverage

Section 03
Technology Stack
Full decision table with version and rationale
🏛️
Database Decision: MongoDB over PostgreSQL
Menu items vary wildly across restaurants (flexible schema). Nested documents map naturally to cart items, order line items, and embedded delivery addresses. JSON-native eliminates impedance mismatch with Node.js/TypeScript. Built-in TTL indexes handle cart expiry. Horizontal sharding for future scale. PostgreSQL would win for strict financial auditing — MongoDB wins here for agility.

Middleware Implementation

// backend/src/middleware/auth.middleware.ts
export const authenticate = async (req, res, next) => {
  const token = req.cookies.accessToken;
  if (!token) return next(new AppError('Unauthorized', 401));
  const payload = jwt.verify(token, process.env.JWT_SECRET) as JwtPayload;
  req.user = { id: payload.userId, role: payload.role };
  next();
};

export const authorize = (...roles: Role[]) => (req, res, next) => {
  if (!roles.includes(req.user.role))
    return next(new AppError('Forbidden', 403));
  next();
};

Idempotency & Retry Safety

Idempotency Key Pattern
// Generated client-side
const idempotencyKey =
  `${userId}-${orderId}-${Date.now()}`;

// Backend: check before processing
const existing = await Payment.findOne(
  { idempotencyKey }
);
if (existing) return existing; // return cached
Checksum Verification
// backend/src/services/payment.service.ts
import PaytmChecksum from 'paytmchecksum';

const isValid = await
  PaytmChecksum.verifySignature(
    body, MERCHANT_KEY, checksum
  );

if (!isValid)
  throw new AppError('Invalid checksum', 400);
⚠️
Critical Security Note
Always verify payment status via Paytm's Transaction Status API from the backend — never trust client-side callback parameters alone. The webhook route must not be behind authentication middleware but MUST verify the Paytm checksum on every call.

  orderId: string, event: OrderEvent, payload: OrderEventPayload
) => {
  // Publish to Redis — all instances receive and re-emit
  redisClient.publish('order-events', JSON.stringify({ orderId, event, payload }));
};

// Socket.IO setup
io.on('connection', (socket) => {
  socket.on('join:order', ({ orderId }) => socket.join(`order:${orderId}`));
  socket.on('join:restaurant', ({ restaurantId }) => socket.join(`restaurant:${restaurantId}`));
});
Section 11
Security Architecture
Defense in depth — transport, application, and data layer
🔒
Transport Layer
  • HTTPS everywhere (TLS 1.3)
  • Nginx: HSTS, SSL certificate (Let's Encrypt)
  • Vercel: auto-HTTPS on all deployments
  • HTTP→HTTPS redirect enforced
🛡️
Application Layer
  • Helmet: CSP, X-Frame-Options, HSTS
  • CORS: whitelist allowed origins only
  • JWT in HTTP-only, Secure, SameSite=Strict cookies
  • Zod validation on all request bodies
  • bcrypt rounds: 12 for password hashing
⚡
Rate Limiting
  • General API: 100 req / 15 min
  • Auth routes: 5 req / 15 min (brute force)
  • Order creation: 10 req / min
  • Backed by Redis (distributed)
🗄️
Data Layer
  • MongoDB Atlas IP whitelist
  • Separate DB users per service (least privilege)
  • Idempotency keys on payments
  • Paytm checksum verification on webhook
  • ObjectId validation on all params
