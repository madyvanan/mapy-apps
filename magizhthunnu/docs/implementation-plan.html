Phase 03
Database Design
MongoDB Atlas · Mongoose 8 · 7 collections with indexing strategy
CollectionKey FieldsSpecial IndexNotes
users email, role, addresses[], passwordHash email (unique) passwordHash: select:false, bcrypt rounds 12
restaurants ownerId, cuisineTypes, address.location, isOpen, rating address.location (2dsphere), name (text), {cuisineTypes, isOpen} compound GeoJSON Point for geo-proximity queries
menuItems restaurantId, category, price, isVeg, isAvailable, customizations[] {restaurantId, category} compound Flexible schema for customizations (size, toppings)
carts userId (unique), restaurantId, items[], totalAmount userId (unique), updatedAt (TTL 24h) TTL index auto-deletes abandoned carts after 24 hours
orders userId, restaurantId, status, paymentStatus, idempotencyKey idempotencyKey (unique), {userId, createdAt} compound Shard key: userId (hashed) for horizontal scale
payments orderId, amount, gateway, gatewayPaymentId, idempotencyKey, status orderId (unique), idempotencyKey (unique) Raw Paytm response stored in metadata field
reviews userId, restaurantId, orderId, rating, comment, images[] orderId (unique) — one review per order helpfulCount for community ranking
💡
MongoDB over PostgreSQL — Why
Menu items vary wildly across restaurants (flexible schema). Nested documents map naturally to cart items, order line items, and embedded delivery addresses. TTL indexes handle cart expiry natively. Horizontal sharding on userId for orders scale. PostgreSQL would win for strict financial auditing — MongoDB wins here for agility and schema flexibility.

JWT Authentication Flow

1
Login → Issue Tokens
bcrypt.compare → sign accessToken (15min) + refreshToken (7d) → store refreshToken in Redis
2
Set HTTP-only Cookie
Set-Cookie: accessToken; httpOnly; Secure; SameSite=Strict — XSS cannot steal token
3
Authenticate Middleware
Read cookie → verify JWT → attach req.user = { id, role } → next()
4
Authorize Middleware
authorize('admin', 'restaurant') — returns 403 if role not in list
5
Token Refresh
POST /api/auth/refresh → validate refreshToken in Redis → issue new accessToken
Phase 06
Payments + Real-Time Tracking
Paytm integration · Socket.IO · BullMQ · Redis Pub/Sub

Paytm Payment Flow

1
Customer clicks "Pay Now"
Frontend sends POST /api/payments/initiate with { orderId, idempotencyKey }
2
Backend creates Payment doc + calls Paytm
Status: pending → Paytm Transaction API → returns txnToken
3
Frontend renders Paytm JS Checkout
Customer completes via UPI / Card / Wallet on Paytm's hosted page
4
Paytm Webhook (most reliable path)
POST /api/payments/webhook → verify checksum (CRITICAL) → update Payment + Order → emit Socket.IO → queue email
5
Customer sees live tracking
Socket.IO order:confirmed event navigates frontend to /orders/:id/track
⚠️
Critical: Webhook Checksum
The webhook route is public (no auth middleware). It MUST verify the Paytm checksum via PaytmChecksum.verifySignature(body, MERCHANT_KEY, checksum) before trusting any data. Never update order status based on client-side callback alone.

Phase 12 — Additional Feature
Tamil / English Language Support
react-i18next · Toggle in Navbar · Persisted to localStorage · Default: English
🌐
New Feature — Not in Original System Design
All app UI text will switch between English (default) and Tamil (தமிழ்) based on user selection. The selected language persists across sessions via localStorage. No backend changes are needed — only frontend UI strings change. Restaurant/menu names stored in DB display as-is (Tamil names already render correctly in Unicode).

Implementation Strategy

📦
Library: react-i18next
  • Industry standard for React i18n
  • Built-in useTranslation() hook — minimal boilerplate
  • i18next-browser-languagedetector for localStorage persistence
  • Zero backend changes needed
  • Works with TypeScript (typed keys)
🔁
Language Toggle UX
  • Single toggle button in Navbar (top-right)
  • Shows "🇮🇳 தமிழ்" when current lang is English
  • Shows "🌐 English" when current lang is Tamil
  • Instant switch — no page reload needed
  • Preference saved to localStorage automatically

i18n Initialization

// frontend/src/i18n/index.ts
import i18n from 'i18next';
import { initReactI18next } from 'react-i18next';
import LanguageDetector from 'i18next-browser-languagedetector';
import en from './locales/en/translation.json';
import ta from './locales/ta/translation.json';

i18n
  .use(LanguageDetector)
  .use(initReactI18next)
  .init({
    resources: {
      en: { translation: en },
      ta: { translation: ta },
    },
    fallbackLng: 'en',         // default language
    defaultNS: 'translation',
    detection: {
      order: ['localStorage', 'navigator'],
      caches: ['localStorage'],
    },
    interpolation: { escapeValue: false },
  });

export default i18n;

Language Switcher Component

// frontend/src/components/ui/LanguageSwitcher.tsx
import { useTranslation } from 'react-i18next';

const LanguageSwitcher = () => {
  const { i18n } = useTranslation();
  const toggle = () =>
    i18n.changeLanguage(i18n.language === 'en' ? 'ta' : 'en');

  return (
    <button onClick={toggle}
      className="flex items-center gap-1 px-3 py-1.5 rounded-md
                 border border-gray-200 text-sm font-medium hover:bg-gray-50">
      {i18n.language === 'en' ? '🇮🇳 தமிழ்' : '🌐 English'}
    </button>
  );
};

export default LanguageSwitcher;
